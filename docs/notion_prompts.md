# Notion統合プロンプトテンプレート

このドキュメントは、Claude DesktopでNotion MCPサーバーを使用してTODOリスト管理を行うためのプロンプトテンプレート集です。

## 基本的な使用方法

1. Claude Desktopで以下のプロンプトをコピー&ペーストして使用
2. `{変数名}`の部分を実際の値に置き換えて実行
3. 各プロンプトは独立して使用可能ですが、順序立てて実行することを推奨

## 1. Notion TODOリスト作成用プロンプトテンプレート

### 1.1 TODOデータベース初期作成

```
Notion MCPサーバーを使用して、以下の構造でTODOデータベースを作成してください：

データベース名: "スケジュール自動化 TODO"
プロパティ:
- 完了 (Checkbox): タスクの完了状態
- タスク名 (Title): タスクのタイトル  
- カテゴリ (Select): Email, Slack, GitHub, Calendar
- 優先度 (Select): High, Medium, Low
- 期限 (Date): タスクの期限
- 完了予定日 (Date): タスクの完了予定日
- 完了日 (Date): タスクが実際に完了した日
- ソースURL (URL): 元の情報へのリンク
- 説明 (Rich Text): 詳細情報
- ステータス (Select): 未対応, 進行中, 完了
- 作成日 (Created Time): 自動設定
- 更新日 (Last Edited Time): 自動設定

作成後、データベースIDを教えてください。
```

### 1.2 単一TODOアイテム作成

```
Notion MCPサーバーを使用して、以下の情報でTODOアイテムを作成してください：

データベースID: {DATABASE_ID}
タスク名: {TASK_TITLE}
カテゴリ: {CATEGORY}
優先度: {PRIORITY}
期限: {DUE_DATE}
完了予定日: {EXPECTED_COMPLETION_DATE}
ソースURL: {SOURCE_URL}
説明: {DESCRIPTION}
ステータス: 未対応

作成が完了したら、作成されたページのIDとURLを教えてください。
```

### 1.3 バッチTODOアイテム作成

```
Notion MCPサーバーを使用して、以下のTODOアイテムリストを一括作成してください：

データベースID: {DATABASE_ID}

TODOアイテム:
{TODO_ITEMS_JSON}

各アイテムの作成状況と、作成されたページIDのリストを教えてください。
```

## 2. カテゴリ別データ分類プロンプト例

### 2.1 Gmail データ分類

```
以下のGmailデータをNotion TODOアイテムに変換してください：

Gmail情報:
- 件名: {EMAIL_SUBJECT}
- 送信者: {SENDER}
- 受信日時: {RECEIVED_DATE}
- メールURL: {EMAIL_URL}

変換ルール:
- タスク名: メール件名をそのまま使用
- カテゴリ: "Email"
- 優先度: 送信者のドメインが会社ドメインなら "High"、その他は "Medium"
- 期限: 受信日+2日
- 完了予定日: 受信日+1日
- ソースURL: メールURL
- 説明: "送信者: {SENDER}, 受信日時: {RECEIVED_DATE}"
- ステータス: "未対応"

Notion MCPサーバーを使用してTODOアイテムを作成してください。
```

### 2.2 Slack データ分類

```
以下のSlackメンションデータをNotion TODOアイテムに変換してください：

Slack情報:
- メッセージ内容: {MESSAGE_CONTENT}
- 送信者: {SENDER}
- チャンネル名: {CHANNEL_NAME}
- 投稿日時: {POSTED_DATE}
- メッセージURL: {MESSAGE_URL}

変換ルール:
- タスク名: メッセージ内容の最初の50文字 + "への返信"
- カテゴリ: "Slack"
- 優先度: チャンネル名に "urgent" や "重要" が含まれる場合 "High"、その他は "Medium"
- 期限: 投稿日+1日
- 完了予定日: 投稿日+8時間
- ソースURL: メッセージURL
- 説明: "送信者: {SENDER}, チャンネル: {CHANNEL_NAME}, 投稿日時: {POSTED_DATE}"
- ステータス: "未対応"

Notion MCPサーバーを使用してTODOアイテムを作成してください。
```

### 2.3 GitHub データ分類

```
以下のGitHubイシューデータをNotion TODOアイテムに変換してください：

GitHub情報:
- イシュータイトル: {ISSUE_TITLE}
- リポジトリ名: {REPOSITORY_NAME}
- ラベル: {LABELS}

- 期限: 作成日+7日（マイルストーンがある場合はその日付）
- 完了予定日: 作成日+5日
- ソースURL: イシューURL
- 説明: "リポジトリ: {REPOSITORY_NAME}, ラベル: {LABELS}, 作成日: {CREATED_DATE}"
- ステータス: "未対応"

Notion MCPサーバーを使用してTODOアイテムを作成してください。
```

### 2.4 Google Calendar データ分類

以下のGoogle CalendarイベントデータをNotion TODOアイテムに変換してください：

- 終了時刻: {END_TIME}

- ソースURL: イベントURL
- 説明: "場所: {LOCATION}, 時間: {START_TIME} - {END_TIME}"
- ステータス: "未対応"

## 3. 重複チェックと更新処理プロンプト例

### 3.1 重複チェック実行

```
Notion MCPサーバーを使用して、以下の条件で重複TODOアイテムをチェックしてください：

データベースID: {DATABASE_ID}
チェック対象:
- タスク名: "{TASK_TITLE}"
- カテゴリ: "{CATEGORY}"
- ソースURL: "{SOURCE_URL}"

検索条件:
1. タスク名が完全一致するアイテム
2. ソースURLが完全一致するアイテム
3. カテゴリが同じで、タスク名が80%以上類似するアイテム

重複が見つかった場合は、既存アイテムのページIDとタイトルを教えてください。
重複がない場合は、新規作成可能と報告してください。
```

### 3.2 既存アイテム更新

```
Notion MCPサーバーを使用して、既存のTODOアイテムを更新してください：

ページID: {PAGE_ID}
更新内容:
- 優先度: {NEW_PRIORITY}
- 期限: {NEW_DUE_DATE}
- 完了予定日: {NEW_EXPECTED_DATE}
- 説明: {UPDATED_DESCRIPTION}
- ステータス: {NEW_STATUS}

更新理由: 重複データの統合により最新情報に更新

更新完了後、更新されたプロパティの一覧を教えてください。
```

### 3.3 重複アイテム統合

```
Notion MCPサーバーを使用して、重複するTODOアイテムを統合してください：

保持するアイテム（メイン）:
- ページID: {MAIN_PAGE_ID}
- タスク名: {MAIN_TASK_TITLE}

削除するアイテム（重複）:
- ページID: {DUPLICATE_PAGE_ID}
- タスク名: {DUPLICATE_TASK_TITLE}

統合処理:
1. メインアイテムの説明欄に重複アイテムの情報を追記
2. より厳しい期限がある場合は期限を更新
3. より高い優先度がある場合は優先度を更新
4. 重複アイテムを削除

統合完了後、最終的なメインアイテムの内容を教えてください。
```

## 4. 優先度と期限自動設定プロンプト例

### 4.1 優先度自動判定

```
以下の情報を基に、TODOアイテムの優先度を自動判定してください：

判定対象:
- カテゴリ: {CATEGORY}
- タスク名: {TASK_TITLE}
- 送信者/作成者: {CREATOR}
- キーワード: {KEYWORDS}
- 作成日時: {CREATED_DATE}

判定ルール:
【High優先度】
- Email: 会社ドメインからのメール、件名に「緊急」「至急」「ASAP」
- Slack: チャンネル名に「urgent」「重要」、メンションが複数回
- GitHub: ラベルに「bug」「critical」「security」
- Calendar: 1時間以内に開始予定のイベント

【Medium優先度】
- Email: 外部からのビジネスメール
- Slack: 通常のメンション
- GitHub: 通常のイシュー、「enhancement」以外
- Calendar: 通常のイベント

【Low優先度】
- Email: ニュースレター、自動通知
- GitHub: 「enhancement」「documentation」ラベル
- その他: 上記に該当しないもの

判定結果と理由を教えてください。
```

### 4.2 期限自動設定

```
以下の情報を基に、TODOアイテムの期限を自動設定してください：

設定対象:
- カテゴリ: {CATEGORY}
- 優先度: {PRIORITY}
- 作成日時: {CREATED_DATE}
- 関連イベント日時: {RELATED_EVENT_DATE}

設定ルール:
【Email】
- High優先度: 作成日+1日
- Medium優先度: 作成日+2日
- Low優先度: 作成日+7日

【Slack】
- High優先度: 作成日+4時間
- Medium優先度: 作成日+1日
- Low優先度: 作成日+3日

【GitHub】
- High優先度: 作成日+2日
- Medium優先度: 作成日+7日
- Low優先度: 作成日+14日

【Calendar】
- 全優先度: イベント開始時刻

計算された期限日時を教えてください。
```

## 5. 完了予定日・完了日の自動設定プロンプト例

### 5.1 完了予定日自動設定

```
以下の情報を基に、TODOアイテムの完了予定日を自動設定してください：

設定対象:
- カテゴリ: {CATEGORY}
- 優先度: {PRIORITY}
- 期限: {DUE_DATE}
- 作成日時: {CREATED_DATE}

設定ルール:
【基本ルール】
- 完了予定日 = 期限 - バッファ時間

【バッファ時間】
- High優先度: 期限の25%前（最低2時間）
- Medium優先度: 期限の50%前（最低4時間）
- Low優先度: 期限の75%前（最低1日）

【カテゴリ別調整】
- Email: バッファ時間 × 0.8
- Slack: バッファ時間 × 0.6
- GitHub: バッファ時間 × 1.2
- Calendar: バッファ時間なし（期限と同じ）

計算された完了予定日時を教えてください。
```

### 5.2 完了日自動設定

```
Notion MCPサーバーを使用して、TODOアイテムの完了処理を実行してください：

対象アイテム:
- ページID: {PAGE_ID}
- タスク名: {TASK_TITLE}

完了処理:
1. 完了チェックボックスをONに設定
2. 完了日を現在日時に設定
3. ステータスを「完了」に変更
4. 説明欄に完了日時を追記

更新内容:
- 完了: ✓
- 完了日: {CURRENT_DATETIME}
- ステータス: 完了
- 説明: 既存の説明 + "\n完了日時: {CURRENT_DATETIME}"

処理完了後、更新されたアイテムの情報を教えてください。
```

### 5.3 一括完了処理

```
Notion MCPサーバーを使用して、複数のTODOアイテムを一括完了処理してください：

対象アイテム:
{COMPLETED_ITEMS_LIST}

各アイテムに対して以下の処理を実行:
1. 完了チェックボックスをONに設定
2. 完了日を現在日時に設定
3. ステータスを「完了」に変更

処理完了後、各アイテムの処理結果（成功/失敗）を報告してください。
```

## 6. 統合ワークフロープロンプト例

### 6.1 全サービス統合処理

```
以下の手順で、全サービスからのデータを統合してNotion TODOリストを更新してください：

1. Gmail MCPサーバーで未読メールを取得
2. Slack MCPサーバーで未返信メンションを取得  
3. GitHub MCPサーバーで未対応イシューを取得
4. Google Calendar MCPサーバーで今日の予定を取得
5. 各データをカテゴリ別に分類
6. Notion MCPサーバーで重複チェック実行
7. 新規TODOアイテムを作成
8. 既存アイテムを必要に応じて更新

データベースID: {DATABASE_ID}
処理日時: {CURRENT_DATETIME}

各ステップの実行結果と、最終的に作成/更新されたTODOアイテム数を報告してください。
```

### 6.2 エラーハンドリング付き統合処理

```
以下の手順で、エラーハンドリングを含む統合処理を実行してください：

処理手順:
1. 各MCPサーバーの接続確認
2. データ取得（エラー時は該当サービスをスキップ）
3. データ変換（不正データは除外）
4. Notion統合（重複チェック含む）
5. 処理結果レポート作成

エラーハンドリング:
- API接続エラー: 該当サービスをスキップして継続
- データ形式エラー: 該当データを除外して継続
- Notion書き込みエラー: リトライ（最大3回）

データベースID: {DATABASE_ID}

処理完了後、以下の情報を報告してください:
- 成功したサービス数
- 取得できたデータ数（サービス別）
- 作成されたTODOアイテム数
- 発生したエラーの詳細
```

## 使用上の注意事項

1. **環境変数の設定**: 各MCPサーバーが正しく設定されていることを確認してください
2. **レート制限**: 大量のデータ処理時は適切な間隔を空けて実行してください
3. **データ検証**: 作成されたTODOアイテムの内容を定期的に確認してください
4. **バックアップ**: 重要なNotionデータは事前にバックアップを取ってください

## トラブルシューティング

### よくある問題と解決方法

1. **MCPサーバー接続エラー**
   - MCP設定ファイルの確認
   - 環境変数の設定確認
   - Claude Desktopの再起動

2. **Notion書き込みエラー**
   - データベースIDの確認
   - プロパティ名の確認
   - 権限設定の確認

3. **重複データの問題**
   - 重複チェックロジックの調整
   - 手動での重複削除
   - データベース構造の見直し
